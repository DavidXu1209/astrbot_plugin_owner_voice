# 按需语音（astrbot_plugin_owner_voice）

一个 AstrBot 插件：主人在私聊里要听语音时，把回复念成中文女声发出来；刚要过之后的大约 5 分钟，后面的回复也用语音。平时她主动关心、叮嘱时有小概率用语音，晚上 10 点后这个概率略高一点。没有配置 BreezeBlue 音色时，自动使用免 Key 的微软 edge-tts 声音。深夜主人道晚安时，还可以按另一套概率主动回一条晚安语音（有频率上限）。

- 插件名：`astrbot_plugin_owner_voice`
- 平台：`aiocqhttp`（QQ 个人号 / OneBot v11）
- 版本：0.2.11
- 作者：David Xu

---

## 功能特性

1. **按需语音**：主人在私聊里说“用语音说”“发个语音”“语音：你好”“语音回我”“说给我听”等明确要求时，插件会把 AI 这一次的文字回复合成语音，替换成 QQ 语音消息发出。明确要过之后的大约 5 分钟里，后面每条回复也都念成语音；他说「别用语音」就提前结束。
2. **只认主人私聊**：必须同时满足“平台是 aiocqhttp、是私聊、会话 ID 与配置完全一致、发送者 QQ 与配置一致”，群里、别人、陌生会话都不触发。
3. **不额外调用模型**：只在原有的一次 LLM 请求上追加一段系统提示，不会为了生成语音再问一次模型，省 token、也不会改变上下文。
4. **BreezeBlue 云端音色（可选）**：填好 `breeze_api_key` 与 `breeze_voice_id` 后，使用 BreezeBlue 的 TTS 接口合成，支持语速、演绎提示和逐句语气。
5. **微软免 Key 兜底**：没配 BreezeBlue、配置不完整、或 BreezeBlue 调用失败时，自动退回 edge-tts 的 `zh-CN-XiaoyiNeural`（晓伊）声音，语速 +5%、音高 +12Hz，不需要任何账号或密钥。
6. **隐藏语气标记**：模型可以在回复最前面写 `【语气：委屈带哭腔】` 这样的标记；只有 BreezeBlue 会把它当成语气提示，标记本身会从文本里删掉，绝不显示给用户。
7. **主动关心的小概率语音**：主人说自己出门、到家、累了、吃饭这类话，或者回复本身是很短的叮嘱时，平时大约 8% 的概率念成语音，北京时间 22:00 到次日 06:00 提高到大约 12%。两次之间至少隔 20 分钟。回答具体问题不会因此被念出来。
8. **深夜晚安主动语音**：北京时间 21:00 到次日 03:00，主人说“晚安”“去睡了”等非问句时，有一定概率把这次回复念成晚安语音；滚动 7 天内有次数上限，两次之间至少隔 2 天。这条和上面的关心语音分开算。
9. **语音文本清洗**：合成前会去掉 `[[meme:…]]` 标记、把动作描写去掉、把括号里的“笑”变成 `[笑]`、去掉“呜呜/嘤嘤”等拟声字、把多段文字用逗号连成可朗读的句子。
10. **失败保留文字**：合成失败、回复过长（超过 600 字）、回复里已经有语音消息时，原样保留文字回复，不自动重试、不报错给用户。
11. **自动清音频**：每次成功合成后顺带删除超过 24 小时的旧 WAV（只删本插件生成的 32 位十六进制文件名），不会堆积。
12. **语气试听命令**：BreezeBlue 配置好后，主人可以在私聊里发 `/语音试听`，用同一句话分别以“平常 / 惊喜 / 委屈带哭腔 / 小声撒娇”四种语气各念一遍。

## 适用场景 / 不适用场景

### 适合

- 只有一个固定主人、希望 AI 偶尔用语音回复的 QQ 私聊机器人。
- 想要“想听的时候才听语音”，其他时候保持文字、不打扰的场景。
- 想试听不同语气、又不想自己搭本地 TTS 服务的场景。
- 服务器能访问外网（微软 edge-tts 或 BreezeBlue）。

### 不适合

- **群聊**：本插件只处理主人私聊，群消息永远不会被念成语音（这是设计如此）。
- **多个主人**：配置里只有一个 `owner_session`，只认一个 QQ。
- **非 aiocqhttp 平台**：代码里写死了 `event.get_platform_name() == 'aiocqhttp'`，Telegram、QQ 官方接口、飞书等平台不会触发。
- **完全离线环境**：edge-tts 需要联网访问微软在线语音服务，BreezeBlue 需要联网访问其 API。
- **想把收到的语音转成文字**：本插件不做语音识别，也不处理别人发来的语音。
- **希望逐字流式播放**：这里是整段合成后再发一条语音，不支持边生成边播放。

## 工作原理

### 1. 收到主人消息、调模型之前

`main.py` 里的 `mark_requested`（`@filter.on_llm_request()`）在 LLM 请求发出前触发：

1. 先做权限判断 `allowed(event)`：平台必须是 `aiocqhttp`；必须是私聊；`unified_msg_origin` 必须与 `owner_session` 完全相等；发送者 QQ 必须等于 `owner_session` 最后一段；`owner_session` 必须能拆成 `平台:消息类型:QQ` 三段，且消息类型是 `FriendMessage`。
2. 不是主人私聊，直接返回，什么都不做。
3. 如果是主人私聊，判断这句话是不是在要语音：
   - 以 `语音：`、`/语音 `、`语音回复`、`语音说` 等开头；
   - 或句子里出现“用语音说”“发个语音”“语音回我”“说给我听”“想听你的声音”“语音语音”“我要听语音”“语音版”“给我语音”等自然说法；
   - 明确要过语音之后的大约 5 分钟内，后面每条私聊都算还在要；他说「别用语音」会提前结束；
   - 同时排除“别用语音”“不要发语音”“你会用语音吗”“文档里写着‘语音：你好’”“我刚才听了语音”“不想听语音”这类否定、陈述或引用。
4. 需要语音时，给事件打一个内部标记（`_owner_voice_requested`），并向本次系统提示追加要求：只用标准普通话口语、正文尽量不超过 180 字、最前面加一个 `【语气：…】` 标记、不要解释合成过程、不要加动作描写和颜文字，也不要写「刚才那条就是语音」「我连发了几条」。同时写入一条系统事实：上一条实际发出去的是文字还是语音（模型自己看不到这个区别）。
5. 如果这句话不是要语音，再判断是否满足“深夜晚安”条件（见下），满足时打上晚安标记并追加另一段系统提示（要求一两句、不超过 60 字、带语气标记）。

### 2. 模型正常回复

模型只按普通方式回复一次，插件不拦截、不重写、不额外请求。

### 3. 回复即将发出时：文字换成语音

`speak_when_requested`（`@filter.on_decorating_result()`）在消息发出前触发：

1. 再次做一次 `allowed(event)` 检查。
2. 先把回复里所有 `【语气：…】` 标记摘掉（无论这次是否真的合成语音，标记都不会显示出来），记下语气。
3. 没有内部标记 → 直接返回，文字原样发出。
4. 取出回复中的所有纯文本段，去掉 `[[meme:…]]`；如果文本为空、超过 600 字，或回复里已经有 `Record`（语音）段，则保留文字。
5. 调用 `synthesize()` 合成，成功后把文字换成一条 `Record.fromFileSystem(...)`。图片、表情包组件会留在语音后面。文字里的 `[[meme:…]]` 不会被念出来；如果这时还没有变成图片，会单独留一段标记，让后面的表情插件继续把它变成图。
6. 合成失败（网络、超时、返回内容不对等）只记一条 warning 日志：“按需语音暂不可用，保留本次文字回复。”，用户仍收到完整文字。
7. 如果这次是“主动晚安语音”并且发送成功，会把当前时间记进 `spontaneous.json`，用于后续频率限制。
8. 最后清理 `audio/` 目录里超过 24 小时的旧音频文件。

```
主人私聊消息
   │
   ├─ allowed()? ── 否 ──→ 完全不管，文字照常
   │
   └─ 是
        ├─ 要语音? ── 是 ──→ 打标记 + 追加“普通话/语气标记/≤180字”提示
        ├─ 深夜晚安? ─ 是 ──→ 打标记 + 追加“晚安/≤60字”提示
        └─ 否 ──────────────→ 不管
   │
   ▼
LLM 正常生成一条回复
   │
   ▼
on_decorating_result
   ├─ 摘掉【语气：…】
   ├─ 无标记 / 文本为空 / >600 字 / 已有语音 → 保留文字
   └─ 有标记 → synthesize()
          ├─ BreezeBlue 已配置 → 云端合成（失败自动退回微软）
          └─ 未配置 / 失败   → edge-tts 微软声音
   │
   ▼
MP3 → imageio-ffmpeg 转 24 kHz 单声道 WAV → Record 语音消息
   │
   ▼
发出；晚安语音记录时间；清理 24h 前旧音频
```

### 4. 合成链路细节

- **文本处理**：去掉「刚才那条就是语音 / 连发了几条 / 没点开」这类误认自己发过语音的句子 → 去 `[[meme:…]]` → 括号内含“笑”的改成 `[笑]` → 其他括号动作描写删除 → 多段用逗号连接 → 去“呜/嘤”拟声字 → 压缩多余空格。
- **BreezeBlue**：`POST https://api.breeze.blue/v1/text-to-speech/{voice}`，`output_format=mp3_24000_128`，请求头带 `xi-api-key`；请求体包含文本、`language_code=zh`、语速（夹在 0.5–2.0）和演绎提示（最多 300 字）；模型给出的语气会拼在演绎提示最前面。
- **截断重试**：BreezeBlue 返回的 MP3 是 CBR（代码按每秒 16000 字节估算时长）。如果字数 ≥6 且“估算朗读时长”明显短于 0.12 秒/字，就判定被提前截断；遇到 429（繁忙）或截断，最多重试 3 次，仍然失败就退回微软声音。
- **微软 edge-tts**：`zh-CN-XiaoyiNeural`，语速 `+5%`，音高 `+12Hz`，35 秒超时。
- **转码**：用 `imageio-ffmpeg` 自带的 ffmpeg 二进制转成 24 kHz、单声道、PCM 16-bit WAV，12 秒超时，不改系统 PATH；转换完成后删除中间 MP3。
- **校验**：最终音频必须在 512 字节到 5,000,000 字节之间，否则视为失败。

### 5. 数据存放

- 音频目录：`StarTools.get_data_dir('astrbot_plugin_owner_voice') / 'audio'`，在 AstrBot 4.9.2+ 的插件数据规范下通常是 `data/plugin_data/astrbot_plugin_owner_voice/audio/`。
- 状态文件：同级的 `spontaneous.json`。`sent` 是晚安语音的时间戳；另外记着上一条主人回复实际是 `text` 还是 `voice`，以及最近一次明确要语音的时间。不存聊天内容。
- 中间 MP3 合成完立即删除；WAV 保留，供平台延迟读取，超过 24 小时在下一次成功合成时清理；晚安记录只保留最近 30 天。

## 安装

### 方式一：AstrBot 插件市场安装（推荐）

1. 打开 AstrBot WebUI → 插件 → 插件市场。
2. 搜索插件名 `astrbot_plugin_owner_voice` 或展示名“按需语音（主人私聊）”。
3. 点击安装，等待依赖自动安装完成，按提示重载插件。
4. 打开插件配置，至少填写 `owner_session`，再把 `enabled` 打开。

> 插件市场的数据来自 `metadata.yaml`；如果你是从市场页直接跳转仓库安装，效果一样。

### 方式二：后台上传 zip

1. 把整个插件文件夹打成 zip（zip 的根目录就是 `astrbot_plugin_owner_voice/`，里面直接是 `main.py`、`metadata.yaml` 等文件，不要多套一层目录）。
2. WebUI → 插件 → 安装插件 → 上传 zip。
3. 安装完成后在插件列表确认没有加载失败，再去配置页填写配置。

### 方式三：手动放进 `data/plugins`

1. 把插件目录放到 AstrBot 的 `data/plugins/astrbot_plugin_owner_voice/`。
2. 安装依赖（如果 AstrBot 没有自动装）：
   ```bash
   pip install -r data/plugins/astrbot_plugin_owner_voice/requirements.txt
   ```
3. 重启 AstrBot，或在 WebUI 插件页点“重载插件”。
4. 打开配置页填写 `owner_session`，启用 `enabled`。

### 安装后必须做的一件事

`enabled` 默认是 `false`，`owner_session` 默认是空字符串——**不填就完全不会生效**。`owner_session` 必须填完整会话 ID，不能只填 QQ 号。

## 配置项详解

所有配置都在 AstrBot WebUI 的插件配置页（由 `_conf_schema.json` 生成），与下面字段一一对应。

| 配置项 | 类型 | 默认值 | 作用 | 示例 | 注意事项 |
| --- | --- | --- | --- | --- | --- |
| `enabled` | bool | `false` | 按需语音总开关 | `true` | 关闭时不发语音、不发晚安语音、不改写回复 |
| `owner_session` | string | `""` | 主人私聊的完整会话 ID | `aiocqhttp:FriendMessage:1234567890` | 必须是 `平台:消息类型:QQ号` 三段，消息类型必须是 `FriendMessage`；填错则插件完全不生效 |
| `spontaneous_goodnight` | bool | `true` | 是否允许主动晚安语音 | `true` | 只在 21:00–03:00、主人说晚安且不是问句时才有机会触发 |
| `spontaneous_per_week` | int | `2` | 滚动 7 天内最多主动发几条 | `2` | 代码另外固定要求两次之间至少隔 2 天，这个间隔不在配置里 |
| `spontaneous_probability` | float | `0.5` | 满足晚安条件时的触发概率 | `0.5` | 0–1；`1` 表示满足条件必触发 |
| `voice_hold_minutes` | float | `5` | 明确要语音后连续念几分钟 | `5` | 这段时间内每条私聊都念成语音；`0` 表示不要连续语音 |
| `care_voice` | bool | `true` | 主动关心时能否小概率用语音 | `true` | 只影响关心、叮嘱，不影响回答具体问题 |
| `care_voice_probability` | float | `0.08` | 平时主动关心的语音概率 | `0.08` | 0–1；两次之间代码还固定至少隔 20 分钟 |
| `care_voice_night_probability` | float | `0.12` | 晚上 10 点后的关心语音概率 | `0.12` | 北京时间 22:00–06:00；只比平时高一点 |
| `breeze_api_key` | string | `""` | BreezeBlue API key | 自行申请后粘贴 | 留空则一直用微软声音；key 只保存在 AstrBot 配置中 |
| `breeze_voice_id` | string | `""` | BreezeBlue 音色 ID | `voc_abc123` | 只接受 4–64 位字母/数字/下划线/连字符；为空或格式非法视为未配置 |
| `breeze_speed` | float | `1.0` | BreezeBlue 语速 | `1.0` | 代码会自动夹到 0.5–2.0 |
| `breeze_instructions` | string | `自然的口语，语气轻松亲近，偶尔带点笑意。` | BreezeBlue 整体演绎提示 | 自定义一句话 | 只取前 300 字；与每条回复的【语气：…】叠加使用 |

### 几个不在配置里、但会影响行为的固定值

- 语音触发判断只在“主人私聊会话 ID 完全匹配”时进行。
- 晚安语音时间窗：北京时间 21:00–23:59 或 00:00–02:59（`hour >= 21 or hour < 3`）。
- 晚安语音两次之间至少间隔 2 天（2 天为固定值）。
- 主动关心语音的夜间概率从 22:00 用到次日 06:00；自动关心语音两次之间至少隔 20 分钟；超过 80 字的回复不会当成关心语音。
- 正常按需回复超过 600 字不合成，保留文字。
- BreezeBlue 最长分 12 段、单段 300 字；微软声音 35 秒超时；BreezeBlue 整体 130 秒超时。
- 旧音频保留 24 小时。

### 怎么拿到 `owner_session`

- 最稳妥的办法：让主人给机器人发一条私聊消息，在 AstrBot 控制台/日志里看这条消息对应的会话标识（`unified_msg_origin`），整段复制到 `owner_session`。
- aiocqhttp 私聊通常形如 `aiocqhttp:FriendMessage:1234567890`。
- 不要只填 QQ 号，也不要填群会话 ID；配置里也不会自动补全。
- 如果之后改过 AstrBot 的会话相关设置，导致会话 ID 变化，需要重新复制一次。

## 使用方法

### 触发语音的常用说法

下面这些写法都经过代码里的规则验证（“语音：你好”这类命令式开头，以及句子里自然提出要求）：

- `语音：你好`
- `/语音 你好`
- `请用语音回答我`
- `用语音回复我一句你好`
- `用语音说`
- `发个语音给我`
- `给我发条语音`
- `你用语音给我加加油`
- `语音回我`
- `说给我听`
- `我想听你的声音`
- `能用语音说一下吗`
- `语音语音`
- `我要听语音`
- `我要听语音版的`
- `用语音给我发消息`
- `给我语音`
- `再听一遍语音`
- `语音呢`

明确要过语音之后的大约 5 分钟里，普通聊天也会念成语音，例如接着说「我到宿舍了」。再说「别用语音」会结束这段连续语音。单独的「求你了」如果已经过了这几分钟，不会再触发。

平时她主动关心时也会小概率念出来：主人说「我到宿舍了」「今天好累」「吃饭了」这类话，或者回复本身是「路上慢点」「别太累，吃点东西」这样的短叮嘱。默认概率白天约 0.08，北京时间 22:00 到次日 06:00 约 0.12。两次自动关心语音至少隔 20 分钟。回答「为什么 / 怎么 / 帮我」这类具体问题不会因此变成语音。

### 这些情况不会触发

- 普通聊天，例如 `你好`。
- 询问能力，例如 `你会用语音回复吗`、`你会不会发语音？`。
- 否定，例如 `别用语音回复`、`不要发语音了`、`不用语音，打字就行`。
- 提到语音这个功能本身，例如 `语音识别好难`、`我发语音给你了`、`文档里写着“语音：你好”`。
- 群聊消息；非主人私聊。

### 主动晚安语音

- 时间：北京时间 21:00 到次日 03:00。
- 内容：主人消息里包含“晚安”“去睡了”“洗洗睡”“困死了”等说法，并且**不是问句**（带“吗/么/?/？”会被排除）。
- 概率：`spontaneous_probability`（默认 0.5）。
- 频率：滚动 7 天最多 `spontaneous_per_week`（默认 2）条，且两次之间至少隔 2 天。
- 关闭：把 `spontaneous_goodnight` 设为 `false`。

### 语气试听命令

- 命令：`/语音试听`（命令名是 `语音试听`，前缀取决于 AstrBot 全局命令前缀设置）。
- 仅主人私聊可用。
- 需要 BreezeBlue 配置完整；否则会收到文字提示“现在没配好 Breeze 声音，备用声音不支持换语气。”
- 会用同一句“你终于回来啦，我等你好久了。”，依次用“① 平常、② 惊喜、③ 委屈带哭腔、④ 小声撒娇”四种语气各发一条语音；某一条失败会发“① 平常：这条没合成出来。”这样的文字。

### 权限边界

- 只对 `owner_session` 指定的那一个私聊会话、那一个 QQ 号生效。
- 群聊、其他 QQ、其他平台一律不合成语音。
- 插件只把**即将发出的回复文本**送去合成，不读取、不转发聊天记录。

## 数据与隐私

- **存了什么**：
  - 合成出来的 WAV 音频，放在 AstrBot 插件数据目录的 `audio/` 下（通常 `data/plugin_data/astrbot_plugin_owner_voice/audio/`）。
  - 晚安语音的发送时间戳，以及「上一条到底发出去的是文字还是语音」「最近一次要语音的时间」「上一次自动关心语音的时间」，放在同级 `spontaneous.json`。不存消息正文。晚安时间戳只保留最近 30 天。
- **保留多久**：音频超过 24 小时会在下一次成功合成时清理；晚安时间戳在每次记录时只保留 30 天内。
- **怎么清空**：直接删除插件数据目录下的 `audio/` 和 `spontaneous.json` 即可，插件会按需重建目录。
- **是否外发**：
  - 使用微软兜底声音时，待朗读的回复文本会发送给微软的在线语音服务（edge-tts 走的是公开的 Edge 朗读接口，不需要账号）。
  - 配置了 BreezeBlue 时，文本会发送给 `api.breeze.blue`。
  - 除此之外插件不向任何地方上传数据；不读取相册、文件、聊天记录。
- **密钥**：`breeze_api_key` 只保存在 AstrBot 配置里；日志只打印错误类型和最多 60 字的错误信息，不会打印 key 和待朗读文本。
- **收到的语音**：插件不做语音识别，别人发来的语音不会被转成文字，也不会被存储。

## 常见问题 FAQ

### 1. 主人在私聊里要语音，但一点反应都没有

按顺序检查：

1. `enabled` 是否为 `true`（默认是 `false`）；
2. `owner_session` 是否为空、是否只填了 QQ 号（必须是完整的 `平台:消息类型:QQ号` 三段）；
3. 是否确实是私聊、平台是否为 aiocqhttp；
4. 说法是否在触发规则内（否定句、疑问句、只是提到“语音”都不会触发）；
5. 这次回复是否超过 600 字。用 `/语音试听` 可以快速验证 BreezeBlue 部分是否正常。

### 2. 语音是普通女声，不是我在 BreezeBlue 里挑的音色

说明 BreezeBlue 没有生效，走了微软兜底。检查 `breeze_api_key` 是否为空、`breeze_voice_id` 是否符合“4–64 位字母/数字/下划线/连字符”，并看日志里有没有“BreezeBlue 音色暂不可用（…），改用微软声音。”。

### 3. 日志出现“BreezeBlue 音色暂不可用”

常见原因是 429 繁忙、额度用完、网络不可达或 key/音色不对。插件会自动退回微软声音，同一条消息仍然能发出语音。可以稍后再试，或改用微软兜底声音。

### 4. `/语音试听` 回复“现在没配好 Breeze 声音”

备用声音不支持切换语气，所以试听功能必须在 BreezeBlue 配置完整时才能用。按第 2 条检查两项配置。

### 5. 晚安语音总是不出现

依次确认：当前是否在 21:00–03:00（北京时间）；消息里是否有“晚安/去睡/洗洗睡”等词；消息是否带“吗/么/?/？”（问句会被排除）；`spontaneous_goodnight` 是否为 `true`；滚动 7 天额度是否已用完；两次之间是否不到 2 天；概率是否太低。

### 6. 为什么群里从来不发语音

这是设计：`allowed()` 只允许主人私聊。群聊里即使 @ 机器人也不会触发。

### 7. 回复太长发不出语音

超过 600 字会保留文字；这是为了避免合成超时和听感太差。可以让模型说得短一点，或把长回复拆成几段说。

### 8. 语音发出来很慢 / 偶尔失败

BreezeBlue 同一时间只允许一个请求（代码注释按免费额度说明，并发会收到 429），插件串行发送，遇到 429 会等待重试（最多 3 次）；整体超过 130 秒或微软声音超过 35 秒都会失败并保留文字。网络不好时偶尔失败属正常现象，整条消息不会在失败后再合成一次。

### 9. 试听时一条成功一条失败

试听是逐条合成的，某条失败只发“这条没合成出来。”文字，其他条照常。通常是瞬时网络/额度问题，重新发一次 `/语音试听` 即可。

### 10. 换了 QQ 或重建了会话，插件不工作了

请重新从日志里复制最新的完整会话 ID 更新 `owner_session`。会话 ID 不一致时，`allowed()` 会直接拒绝。

### 11. 模型回复里出现了“（笑）”之类的动作描写，会不会被念出来

不会。合成前会清理：括号里含“笑”的变成 `[笑]`，其他短括号内容直接删掉；`呜呜/嘤嘤` 这类拟声字也会去掉。`【语气：…】` 标记只交给 BreezeBlue 当语气提示，不会显示也不会念出来。

### 12. 语音能不能只念一部分、保留后半段文字

文字不行：要么整段文字换成语音，要么整段留着。表情包可以一起发。图片组件会留在语音后面；`[[meme:名字]]` 不会被念出来，会单独留下交给表情插件。她不该只说「给你补一张」而不写这个标记。

### 13. 她嘴上说已经发了语音，聊天记录里却是文字

她看不到哪条真正变成了语音，历史里留下的全是文字，所以会把上一句文字说成「刚才那条就是语音」。0.2.9 起，像「语音语音」「我要听语音」「我要听语音版的」这种说法会真的合成；系统提示里也会写明上一条实际是文字还是语音。就算她还是写了「刚才那条就是语音」「我连发了三条」，念出来之前也会把这种句子拿掉，只留下要说的话。合成失败时仍保留文字，但下一句会知道上一条并没有发出去。

### 14. 怎样彻底关掉

把 `enabled` 设为 `false` 并保存即可；卸载插件也不会留下正在运行的任务。历史音频和 `spontaneous.json` 在插件数据目录里，可手动删除。

## 兼容性

- **平台**：仅 `aiocqhttp`（QQ 个人号 / OneBot v11）。在 QQ 官方接口、Telegram、飞书、企业微信等适配器上不会触发（代码里写死平台判断）。
- **与其它改写回复的插件**：如果别的插件也在 `on_decorating_result` 阶段改写消息链，执行顺序取决于 AstrBot 的处理器调度（本插件未验证与具体插件的先后关系）。可能出现“别的插件先把回复换成图片，导致本插件拿不到纯文本而保持原样”，或反过来。遇到冲突时可以只保留一个。
- **与群聊边界类插件**：本插件只在主人私聊工作，群聊类插件只影响群聊，一般可以共存。
- **与主动消息/定时任务插件**：本插件只处理“主人发消息触发的这一轮回复”，不会接管主动推送消息。
- **AstrBot 版本**：`metadata.yaml` 声明 `>=4.16.0`；更低版本未验证。

### 跑测试

测试不依赖真实 QQ 或网络，但需要能 import `astrbot`，所以要在 AstrBot 的 Python 环境里跑：

```bash
py -m unittest discover -s tests -v
```

如果 `py` 指向的不是 AstrBot 用的解释器，请换成 AstrBot 自带的 Python。当前测试覆盖：会话范围判断、触发词正/反例、晚安窗口与配额、BreezeBlue 选择与兜底、文本清洗与分句、截断重试、读取完整响应体等。

### 改代码注意点

- `MARKER` / `SPONTANEOUS` 是事件内部的临时标记，只存在于当前事件对象，不落盘。
- BreezeBlue 的音频是 CBR MP3 帧直接拼接；分段只用于超长文本，分段越多音色越可能漂移。
- `looks_truncated()` 按“每秒 16000 字节、每字约 0.2 秒”估算，改动音频格式（不是 `mp3_24000_128`）时必须同步调整。
- 新增配置项必须同时改 `_conf_schema.json` 和代码里的读取位置，并保持默认值中性可空。
- 合成失败要保留文字，不要把异常抛给 AstrBot 事件链。
- 音频文件名是 32 位 UUID 十六进制；清理逻辑只匹配这种文件名，避免误删其它文件。
